# Reusable brief format

Use this structure when the user requests a durable brief, implementation plan, or Markdown deliverable.

## Source and access scope

- Source title and identifier
- Material actually inspected: full text, abstract, excerpt, screenshot, README, or other
- Access date when the source may change

## Source-backed findings

For each material finding:

- **Finding:** concise paraphrase
- **Evidence location:** page, section, heading, paragraph, timestamp, or file path
- **Confidence:** high, medium, or low based on the inspected material

## Interpretation

Explain what the findings mean for the user's goal. Clearly label this as analysis rather than a source claim.

## Practical applications

Map each selected finding to a concrete design decision, workflow change, test, or implementation task.

## Limits and non-transferable points

Record assumptions, missing material, source-specific mechanisms, conflicting evidence, and ideas that should not be generalized.

## Next actions

Provide a short ordered list of actions that can be completed or tested. Include an observable completion condition where useful.
